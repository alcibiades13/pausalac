# Decisions log

Running log of engineering conventions decided per the master prompt's §81 rule: if a choice doesn't touch money, legal compliance, tax treatment, security, or irreversible data, decide it, document it here, and move on rather than blocking on it. Reference `docs/implementation-plan.md` for the full architecture rationale — this file is just the append-only decision record.

Add new entries at the bottom, in the same table row format, as Phase 1b+ raises new ones (auth session strategy, ERD specifics, permission matrix, etc.).

| Date | Decision | Rationale |
|---|---|---|
| 2026-09-13 | Two canonical spec documents: `Pausalac.md` (Master Development Prompt) and `pausalac-blueprint.md` (Product Blueprint). Earlier `pausalac-product-blueprint.md` (mislabeled duplicate of the master prompt) and `pausalni_product_blueprint.docx` (superseded by the blueprint md) archived to `docs/source/archive/`, not deleted. | User-confirmed after investigating a file-naming mixup during discovery. |
| 2026-09-13 | Monorepo, pnpm workspaces (pinned `pnpm@9.12.0` via corepack). | Keeps a two-person team on one repo; pnpm workspaces are the standard fit for a Django-API + multiple-frontend layout. |
| 2026-09-13 | Layout: `apps/api` (Django), `apps/app` (Vue 3 SPA — the authenticated product), `apps/web` (Nuxt 4 — public marketing site), `packages/ui` (reserved for shared component primitives, empty for now), `packages/config` (shared design tokens + base tsconfig). | Matches blueprint §14.1 explicitly: Vue for the app itself, Nuxt for the marketing layer. |
| 2026-09-13 | Django: one app per business domain under `apps/api/apps/<domain>`, dotted as `apps.<domain>` in `INSTALLED_APPS`. Domains: `accounts, companies, clients, invoices, payments, kpo, limits, taxes, documents, notifications, analytics, subscriptions, integrations, audit` (master prompt §44). `sef`, `fiscalization`, `banking`, `ai` intentionally NOT scaffolded yet — later-phase integration seams. | Avoids a flat, unscoped app namespace at the project root; matches the modular-monolith domain boundaries called out in the spec. |
| 2026-09-13 | Django settings split into `config/settings/{base,dev,staging,production}.py`. `manage.py`/`wsgi.py`/`asgi.py` default to `config.settings.dev`; other environments set `DJANGO_SETTINGS_MODULE` explicitly. | Standard Django convention for keeping environment-specific flags (DEBUG, ALLOWED_HOSTS, SSL/cookie security) out of shared logic. |
| 2026-09-13 | Database: PostgreSQL only, no sqlite fallback anywhere in settings (master prompt §46). `DATABASE_URL` (or discrete `POSTGRES_*` vars) required. | Financial `Decimal`/`NUMERIC` behavior and constraint semantics must match production from day one; sqlite would mask real bugs. |
| 2026-09-13 | Object storage: `django-storages` + S3 backend, pointed at MinIO locally via `AWS_S3_ENDPOINT_URL`. Signed URLs (`AWS_QUERYSTRING_AUTH = True`, 5 min expiry) rather than public files. | Master prompt §26/§103: documents must never be public/predictable filesystem paths. |
| 2026-09-13 | DRF defaults: session auth (placeholder — real auth strategy is a Phase 1b decision), `IsAuthenticated` by default, page-number pagination, `django-filter` + search/ordering backends, URL path versioning (`v1`). | Reasonable DRF starting defaults; none of this is a business-logic commitment, all overridable per-view. |
| 2026-09-13 | Versions pinned: Python 3.12, Django 5.2, DRF 3.18(pinned `~=3.15` in requirements, resolved 3.18), Node 24 (repo requires `>=20`), Vue 3.5, Nuxt 4.5, Tailwind CSS v4 (via `@tailwindcss/vite`, CSS-first `@theme` config — no `tailwind.config.js`). | Current stable majors at bootstrap time; Tailwind v4's CSS-first token approach maps directly onto the blueprint's flat color palette (`docs`/`packages/config/tokens.css`). |
| 2026-09-13 | Shared design tokens live in `packages/config/tokens.css` as a Tailwind v4 `@theme` block, imported by both `apps/app` and `apps/web`. Palette/font values taken verbatim from blueprint §18. | Single source for color tokens avoids drift between the two frontends; matches master prompt §88 ("avoid arbitrary values"). |
| 2026-09-13 | `/health` endpoint added directly in `config/` (not a domain app) — deliberately dependency-free for now (process liveness only, no DB/broker checks). | Master prompt §68 requires a health endpoint from the start; a real readiness check (verifying Postgres/Redis/storage) is deferred until those integrations exist to check. |
| 2026-09-13 | Requirements split into `requirements/{base,dev,production}.txt` rather than a single `requirements.txt` or Poetry/PDM. | Keeps dev-only tooling (pytest, ruff, factory-boy) and prod-only tooling (gunicorn) out of each other's install; no need for a lockfile-based Python tool yet at this scale. |
